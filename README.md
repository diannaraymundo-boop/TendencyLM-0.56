# TendencyLM 0.56

一个个人做的语言模型架构实验。注意力先把输入读一遍,给每个词叠上“倾向”;之后念头(意识流)一拍接一拍往下流,每拍说一个字;说完再让注意力检查一遍,把不可信的字挖掉重填。

> **状态**:实验原型,不是能用的聊天模型。下面的结果照实记录,做到的和没做到的都写了。
>
> 架构设计来自作者,代码由 AI(Claude)按设计落地。

## 作者的话

这是一个用于验证想法可行性的原型AI架构，仅在个人电脑上跑过5.2M参数的版本，模型已具备部分语言能力，但仍然不稳定，且架构上限没有经过数学验证，无法保证。
此架构代码与测试均为AI实现，我提供架构设想与监督，确保实现上与我所想无差别。
我并非科班出身，架构更多出于直觉，仅提供其实现思路，不试图挑战现有架构。
架构的设计宗旨是试图使其具备原生思考与纠错能力，并尽可能减少对注意力机制的依赖，其特点鲜明：
优点：1.注意力计算非常少，且占比不高，这使得即使模型无法并行训练也能达到一个较为合理的速度。
2.原理上具备自我纠错能力。
3.对长上下文的支持应当较纯注意力模型更优。
缺点：1.推理层一次说出一整段话，在此期间没有注意力的上下文修正，因此在语序上更差(无法验证是否存在语序能力)。
2.速度太慢，无论在样本效率还是时间效率上都不如Transformer。
3.训练困难，由于采取了不同的推理链条，导致训练不得不做出相应调整，这也许是样本效率过低的原因之一。
4.待发现

## 设计

### 链条

1. **注意力修正输入。** 注意力一次看完全文,避免漏词,给每个输入词叠上倾向。修正后的词有了和静态词汇不同的词意,倾向里隐含着上下文关系,表示模型脑子里的抽象含义,不再严格对应词表。
2. **推理产出(比喻)意识流。** 不同上下文修正出的版本都不一样,后面还跟着和上下文自洽的语序,所以意识流本身就带着上下文,说话时不用再重复做注意力修正。意识流不是词表里的字,而是一串“含意”,越宽越好,不要损失太多信息。
3. **语言组件翻译。** 把意识流翻译成严格对照词表的字。思考和语言表达就此分开。
4. **注意力检查。** 翻译出的字由注意力检查一次:给每个字置信度,同时给全文重新叠一次倾向,再交给推理。
5. **推理改字。** 做填空:置信度高的字保留,低的挖掉重填,前面和后面的字都看得见。
6. **再翻译,再检查。**

另外:

- **倾向每次都是覆盖**:注意力每跑一次,都在词本身的静态意思上重新给倾向,替换旧的,不累加。
- **注意力只在输入时和检查时跑**,说话时不跑,所以注意力本身可以做得大一些。
- **一次心跳说一个字**,一段话靠连续心跳。训练和生成走同一个循环。
- **输入的词全部保留**,每个词一个向量,不揉成一块;前后顺序靠训练内化。时钟只当心跳,让模型知道现在是第几拍。
- **和 Transformer 的区别**:Transformer 每说一个字,都重新看一遍前面所有的字;这里注意力只把输入理解一次,之后靠一路带下来的意识流往下说。代价是训练时一拍要等上一拍,不能整段并行。

### 一个例子

传入“张三被李四打,谁被打了?”:

| 阶段 | 发生什么 |
|---|---|
| 输入时 | 注意力完整跑 8 轮看完全文,给每个词定改多少,叠上倾向 |
| 第 1 拍 | 推理按第 1 拍的时钟分 4 路读修正后的原文,合出意识流 → 翻译成“张” |
| 第 2 拍 | 第 1 拍的意识流带着说出口的“张”成为新的一列。原文读一份、自己说过的读一份,各分 4 路,合起来 → “四” |
| 第 3、4 拍 | 同上 → “。”、停止符,一段话说完 |
| 检查 | 输入 + “张四。”,注意力完整跑 8 轮,重新覆盖全文的倾向,给每个字置信度。假设“四”置信度低 |
| 填空 | “张”“。”保留,“四”挖空;推理读覆盖后的全文,前后的字都看得见,填出“三” |
| 再检查 | 都可信,结束 |

## 实现

| 地方 | 做法 |
|---|---|
| 词 | 词表 8000 个词,每个词一个 128 维的静态意思 |
| 注意力 | 输入时 8 轮、检查时 8 轮,每轮分 4 路,所有词互相看得见。当前时间(时钟)改变每个词想看谁;同一个词在不同位置的表征不同(按位置转角度) |
| 倾向 | 倾向 = 幅度 × 改动。改动由注意力给;幅度由权重表给,每个词各自 0~1,词和词不互相抢 |
| 意识流 | 512 宽,从推理出来到进入下一拍都不压缩 |
| 说话时怎么读 | 原文一份(每拍一定读)、自己说过的一份(这拍可以不读),各分 4 路,每路一张比例表。比例只由时钟、位置和每列的键决定,不看当前在想什么 |
| 每拍的新一列 | 意识流 × 一个可训练的幅度 + 说出口的字。训练时用答案的字,生成时用自己说的字,说错了由检查和填空来改 |
| 语言组件 | 意识流 → 一层网络压到 128 → 和静态意思表比对,得到每个字的分数 |
| 检查 | 输入 + 说出的字,都从静态意思开始,注意力重新覆盖倾向;注意力的结果过一个小头,给每个字 0~1 的置信度 |
| 填空 | 置信度低于 0.5 的字(一次最多 16 个)挖掉重填。用说那个字时的时钟、站在说它时的位置,和说话一样分两份读,前后的字都看得见;和说话共用推理网络、语言组件 |
| 停止 | 说到停止符就停,最多 256 个字;最多检查、填空 3 次 |

**训练一段话**:输入时注意力跑一次 → 逐拍说完整段,每拍和答案比算损失;新一列带上答案的字,但看不到要预测的字和后面的字;同时按生成时的选法(温度 0.8、前 40 个词)自己选一个字留给检查 → 检查:和答案一样的字教“可信”,不一样的教“不可信”,两类各占一半分量 → 填空:说错的字和检查标为不可信的字挖空重填,和答案比。总损失 = 说话 + 0.5 × 检查 + 0.5 × 填空,误差沿意识流一直传到这段话开头。

**提速**:每拍的时间和读的查询只由第几拍和位置决定,说话前一次算好;训练时答案的字一起过推理网络;交给检查的字说完整段再一起选。结果和每拍现算一样(有测试守着),一步(一批 32 段)从 1.59 秒降到 0.85 秒。现在速度主要受 CPU 发任务的快慢限制,显卡约一半时间在等。

## 实验结果

### 训练

- 数据:[MiniMind](https://huggingface.co/datasets/jingyaogong/minimind_dataset) 的 `pretrain_t2t_mini.jsonl` 和 `sft_t2t_mini.jsonl`,共约 6.6 亿个 token,留 1% 做验证。对话里最后一轮回答是答案,前面是输入;纯文本随机切一刀,前半是输入,后半是答案。
- 每次更新 32 段话(平均约 4,500 个预测),输入最多 512 个词,答案最多 256 个词。
- AdamW,学习率 5e-4 全程不变(前 100 步预热),权重衰减 0.01,梯度裁剪 1.0,随机种子 1234。
- 一张 RTX 3080 10 GB,约 5,000 预测/秒,显存峰值 6.6 GB。练了 262 分钟、18,483 次更新(8,300 万个预测)时停下,存档就是验证损失最低的那次。

验证损失是看着前面真正的字预测下一个字,越低越好。同一批验证段落上的参照:只看词频 6.94;只数“上一个字后面常跟什么” 4.85。

| 更新次数 | 第五版 | 同规模 Transformer | 说对的字 | 填空后说对 |
|---|---|---|---|---|
| 1,113 | 5.691 | 5.556 | 14.6% | 15.2% |
| 2,216 | 5.163 | 5.045 | 18.1% | 19.1% |
| 4,000 | 4.599 | 4.508 | 22.7% | 24.2% |
| 6,362 | 4.224 | 4.115 | 26.4% | 28.6% |
| 9,766 | 3.918 | 3.761 | 29.6% | 32.4% |
| 12,000 | 3.813 | 没有记录 | 31.0% | 33.7% |
| 14,000 | 3.729 | | 31.6% | 34.6% |
| 16,000 | 3.659 | | 32.3% | 35.3% |
| 18,483 | **3.591** | | 33.3% | 36.6% |

- Transformer 那一栏是它自己训练时的验证损失,按连续窗口算,和这里按段落算的不完全是同一把尺子。同一把尺子见下一张表。Transformer 只练到 9,766 次。
- 每 2,000 次更新降的:8,000~10,000 次 0.15,之后 0.09、0.08、0.07、0.06,在放缓,还没停。

### 同一批段落、同一把尺子:按词拆分

| 类别 | 占比 | 第五版(18,483 次) | 同规模 Transformer(9,766 次) |
|---|---|---|---|
| 第一次出现的词 | 39.6% | 4.52 | 4.93 |
| 新的搭配(词出现过,但没跟在前一个词后面出现过) | 30.2% | 3.15 | 3.39 |
| 重复的搭配(这两个词已经连着出现过) | 29.6% | 2.75 | 2.81 |
| 全部 | | **3.57** | 3.82 |

Transformer 只有 9,766 次更新的存档,这张表不是同样更新次数的比较。两边各自换算到这把尺子,9,766 次时第五版大约落后 0.07(粗估)。泄漏检查正常:改填充不影响预测,改答案后半不影响前半,单独算和一批算一样。

### 语序排查

7 组句子,每组原句 A、人名对调 B、换成别的人名 C,比如“张三打了李四。谁被打了?”“李四打了张三。……”“王五打了赵六。……”。只在三句里完全相同的词上比。**对调比例** = A、B 的差别 ÷ A、C 的差别,接近 0 说明只认得有哪些词、分不出顺序。

| 步骤 | 训练后 | 同样配置、没训练过 |
|---|---|---|
| 注意力看完全文后 | 0.65 | 0.08 |
| 叠完倾向 | 0.59 | 0.09 |
| 各自过推理网络 | 0.58 | 0.09 |
| 第 1 拍读完合起来 | 0.52 | 0.08 |
| 第 1 拍意识流 | **0.44** | 0.08 |

- 第 1 拍说什么(分布差别):名字对调只差 0.002~0.21,换人差 0.01~1.47。语序进了意识流,但几乎没改变要说的字。
- 倾向铺到了每个词上:验证段落里 77% 的词倾向超过静态意思的 10%(中位 14%),没有哪个词一家独大。第 1 拍读得最多的是 `<assistant>`(0.35)、`<user>`(0.21)、`<bos>`(0.17)这几个标记。

### 固定测试

| 测试 | 第五版(18,483 次) | 同规模 Transformer(9,766 次) |
|---|---|---|
| 语序:两个人名对调后,第一拍的分布差多少(越大越分得清) | 0.006、0.002、0.003、0.076 | 0.39、0.14、0.20、0.95 |
| 复述:让它原样重复一句话,和原文的相似度(0~1) | 0.50、0.39、0.26 | 0.26、0.17、0.18 |
| 谁被打了:24 句,主动被动各半、名字对调,先说出的是不是被打的人(乱猜约 12 句) | 说话时对 7 句,填空后对 4 句 | |

例子:

- “请原样重复下面这段话:今天天气很好。” → “今天天气很好,但我无法直接获取天气预报。”
- “张三打了李四。谁被打了?” → “张三,这份的一份都是多少?”
- “你好,请介绍一下你自己。” → “你好,你好,你好,我会告诉我你吗?”

### 检查和填空

- 检查会分辨对错:说对的字平均置信度 0.81,说错的字 0.18;判断对 86.8%(全说不可信是 66%)。
- 填空让说对的字从 34.0% 提到 37.0%,说错的字里 5.0% 被改对。
- 生成时检查、填空改得很多,一段回答重填几个到几十个字;“谁被打了”这一项填空后反而少对 3 句。

### 结论

做到的:

- 整条链条在真实文本上跑通,学会了说通顺的中文,损失 3.59,低于只数数的 4.85。
- 检查真的会分辨对错,填空能改对一部分。这是 Transformer 本来没有的部分。
- 倾向铺到了每个词上;注意力把语序编了进去(对调比例 0.65),第一个念头里也留下不少(0.44)。
- 会用前文:重复的搭配比新的搭配低 0.40(Transformer 低 0.58)。

没做到的:

- 按同样更新次数,一直落后同规模 Transformer。
- 没读懂输入的顺序:“谁被打了”24 句只对 4 句,大部分回答根本没提到句子里的两个人;第一拍说什么,对名字对调几乎不变。
- 回答常常跑题、重复。
- 训练一拍要等上一拍,速度受 CPU 限制。

| 语序:“A 被 B 打 谁”答 A,“A 打 B 谁”答 B,考没见过的名字搭配(3,000 步) | 100%、100%、100% |

第一个种子是这条链第一次完整起作用:说话时整句全对 88%,检查标出错字、填空改对后变成 100%。

## 测试

```bash
python -m pytest tests -q
```

59 个测试,守着这些边界:

- 一次心跳一个字;意识流不压缩;意识流和说出口的字都进入下一拍;第 t 拍看不到第 t 个字和后面的字。
- 读原文每一路加起来一定是 1,原文不会被自己说过的挤掉;读和改倾向分开;读的比例不看当前在想什么。
- 每个词的改动幅度各自定;时钟只能通过读的比例起作用。
- 检查只给说出的字打分,倾向从静态意思重新覆盖,只看字、不看意识流;填空看得见前后的字,和说话共用推理网络和语言组件。
- 说话前一次算好的时间和查询,和每拍现算的结果、倒推的误差一样。
- 训练时每个参数都收到误差;完全随机的数据上验证损失仍接近乱猜(没有偷看答案);极小复述任务学得会。

## 怎么运行

需要 Python 3.10 以上和带 CUDA 的 PyTorch(50 系显卡要 CUDA 12.8 以上的版本):

```bash
pip install -r requirements.txt
```

**和附带的模型对话**(只要 `checkpoints/` 和 `data/tokenizer.json`,不用下载数据):

```bash
python generate.py --run checkpoints/flow_amount --prompt "你好"
```

加 `--show` 看每次检查时每个字的置信度、哪些字被重填。

**准备数据**:把 MiniMind 的 `pretrain_t2t_mini.jsonl`、`sft_t2t_mini.jsonl` 放到 `data/raw/`,然后运行(会直接用附带的分词器):

```bash
python prepare_data.py
```

**其他**(训练、测试和排查都要先准备好数据;小任务、测速、跑测试不用):

| 要做什么 | 命令 |
|---|---|
| 从头训练(按分钟停) | `python train.py --model flow --max_minutes 300 --run_name 名字` |
| 接着训练 | `python train.py --model flow --resume true --run_name 名字 --max_minutes 600` |
| 固定测试 | `python evaluate.py checkpoints/flow_amount` |
| 查泄漏、按词拆分 | `python diagnose.py checkpoints/flow_amount` |
| 语序排查 | `python probe_order.py checkpoints/flow_amount`,加 `--untrained` 用没训练过的模型当尺子 |
| 谁被打了 | `python who_was_hit.py checkpoints/flow_amount` |
| 小任务 | `python small_task.py --task copy --seed 1 --steps 4000`,任务还有 `order`、`needle`、`lookup` |
| 测显存和速度 | `python measure.py` |

训练时每验证一次(约每 100 万个预测)往 `runs/名字/进度.txt` 写一行大白话:损失、同样更新次数时同规模 Transformer 的损失、说对的比例、一句回答样例。所有能调的参数都在 `config.py`,命令行可以覆盖,比如 `--attn_rounds 6`。

Windows 上用大小核的 CPU(比如 i5-14600KF)时,系统可能把训练进程调到小核上,速度掉一半。可以在任务管理器里或用 PowerShell 把训练进程限定在大核上。
